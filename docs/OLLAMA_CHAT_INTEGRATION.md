# Intégration mod-ollama-chat

Le commit `a9d14b0...` contient des réglages vérifiés comme `OllamaChat.MaxConcurrentQueries`, `NumPredict`, `NumCtx`, `ThinkMode`, l'historique, les canaux et les chatter. Les presets RealmBox utilisent uniquement ces clés réelles.

Le module est compilé dans les images serveur épinglées mais reste désactivé par configuration. Ollama 0.33.2 n’est téléchargé qu’après confirmation depuis sa release officielle et est refusé si son SHA-256 diffère. RealmBox soumet son allowlist courte à CanIRun, filtre les résultats confortables selon son budget mémoire, puis décide automatiquement du meilleur rapport vitesse estimée/taille de téléchargement parmi les modèles 3B+ ; le 1B est un repli. La taille officielle est affichée avant téléchargement. Après le `pull`, le manifeste local doit correspondre au digest immuable du catalogue. L'inférence s'effectue ensuite sur `127.0.0.1:11435` avec les fonctions cloud coupées.

La vue Dialogues peut installer, activer ou désactiver ce runtime après l’installation du royaume. L'activation et la désactivation exigent toujours que le monde soit fermé. Quand l'IA et son modèle sont déjà actifs, les niveaux silencieux, équilibré et vivant peuvent en revanche être appliqués à chaud par la commande bornée `ollama reload`. Une désactivation conserve les fichiers du modèle dans le répertoire géré et ne déclenche aucun réseau au lancement suivant.

Le preset joueur privilégie les conversations demandées : tout message éligible d'un joueur choisit exactement un bot, sans cooldown artificiel. Le prompt transmis au petit modèle reste volontairement minimal, n'injecte pas l'historique et répète que le dernier message décide seul du français ou de l'anglais. La température est fixée à zéro pour éviter qu'une réponse bascule aléatoirement dans la langue précédente.

Le niveau silencieux coupe les bavardages spontanés et les réponses bot-à-bot. Le niveau équilibré autorise occasionnellement les canaux dire et groupe ; le niveau vivant augmente leur fréquence et garantit la chance de réponse d'un autre bot de groupe éligible. Dans les deux cas, un seul bot est choisi par message, une conversation ne peut produire qu'un rebond, un seul worker LLM traite une file de quatre demandes maximum, et le cooldown par bot reste compris entre 60 et 90 secondes. RealmBox limite en plus les messages à 2 ou 4 par minute dans une même portée et à 4 ou 6 par minute globalement. Les combats, canaux personnalisés et guildes restent exclus.

Le correctif RealmBox du module épinglé rend enfin `RandomChatterMaxBotsPerPlayer` effectif : un passage de bavardage ne peut soumettre qu'une origine par groupe ou zone. Le compteur n'augmente qu'après acceptation réelle par la file. Un changement de profil à chaud recharge d'abord la configuration, réinitialise les anciens délais de bavardage, puis conserve les limites de profondeur et de débit ; ces garde-fous empêchent le flood même lorsque le module de présence rapproche plusieurs dizaines de bots.

Risque principal : le README du commit nomme encore les anciens dépôts `liyunfan1223`, tandis que RealmBox épingle les continuations `mod-playerbots`. Seul un build combiné puis un chargement worldserver peut prouver la compatibilité. Les ordres de gameplay restent séparés de la conversation et bornés par allowlist.
